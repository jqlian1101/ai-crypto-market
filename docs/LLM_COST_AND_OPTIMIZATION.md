## 1. 成本模型基线（重建版）

### 1.1 为什么重建

`DATA_AND_COST_ANALYSIS.md` §4.1.2 存在内部矛盾，导致成本估算不可靠：

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| **E1** | **输出 token 汇总少算 24.4%** | 分档加总 = **1,020,100 / 天**，文档汇总写「输出 ≈ 0.82 M」 | 输出单价是输入 5 倍，所有方案成本被低估约 **20%** |
| **E2** | **异动触发全部按 STANDARD 计费**，与 PRD 22.2.6 冲突 | 22.2.6：INFO→否、WARN→可选、CRITICAL→必须；成本模型对 17.5 次/天一律按 STANDARD 折算 | 成本模型与 PRD 直接矛盾 |
| **E3** | 「全 LIGHT = $13/月」对不上任何一档 | 按 125.268M in / 30.603M out 全部流量实算：`qwen3.7-flash` = **$6.98**，`deepseek-v4-flash` = **$26.26**，`haiku` = **$27.83** | 方案 A 预算失真 |
| **E4** | 含已过期 / 临近到期的促销价 | Gemini 4 Argon 促销至 2026-11-30、3.8 Flash 至 2026-12-31；`haiku-5-5` 超 100K 输入价 ×5 | 硬编码单价的成本报表会失真 |

> **本文的输入 token 基准与 §4.1.2 完全一致**（还原误差 Δ < 10 token/天），**仅修正输出侧**。因此本文数字可与旧文档直接对照。

### 1.3 STANDARD 档内部拆解（成本集中点）

单资产/天：

| 子项 | 调用数/天/资产 | STANDARD 输入/天 | STANDARD 输出/天 | 占 STANDARD 输出 |
|---|---:|---:|---:|---:|
| **异动触发分析** | 17.5 | 310,258 | **92,855** | **52.7%** |
| `analysis_1h` Master 汇总 | 24 | 360,000 | 60,000 | 34.0% |
| `analysis_4h` 子 Agent + Master | 6 | 114,000 | 23,400 | 13.3% |
| **合计** | — | 784,258 | 176,255 | 100% |

**这张表是全部优化的出发点**：STANDARD 档一半以上的输出花在异动触发上，而按 PRD 22.2.6，其中 80% 的触发（INFO + WARN）**本来就不该由 LLM 全额参与**。

### 1.4 输出是真正的杠杆

输出单价普遍是输入的 **5 倍**。这决定三条优化原则的优先级：

1. **优先砍输出，而不是砍输入**——输出占 STANDARD 档费用 72%。
2. **优先砍调用次数，而不是砍单次 token**——每次调用都有固定开销（重复前缀、schema 重复、结构冗余）。
3. **输入用缓存，输出用契约**——缓存是唯一「完全无损」的降本手段。

### 4.1 O1：异动分级参与（单项收益最大）

**现状**（§4.1.2 假设）：17.5 次/天/资产，每次 25,000 in + 6,000 out。
**修正后**（PRD 22.2.6）：仅 CRITICAL 独立调用。

| 级别 | 数量/天/资产 | 现状处理 | 修正后处理 | token 影响（单资产/天） |
|---|---:|---|---|---|
| `CRITICAL` | ~3.5 | STANDARD 级调用 | STANDARD 级调用 | 保留 20% |
| `WARN` | ~10 | STANDARD 级调用 | **Python 写入快照 `recent_warnings` 列表**，Master 顺带读取 | 释放 57% 的异动 in |
| `INFO` | ~4 | STANDARD 级调用 | **零 LLM**，进日报 | 释放 23% 的异动 in |
| **合计** | 17.5 | — | — | **STANDARD in 降 80%、out 降 80%**（仅 O1，不改单次用量） |

**单独效果（脚本实测）**：

| 档位 | 优化前 | 优化后 | 节省 |
|---|---:|---:|---:|
| STANDARD（`ds-pro`） | $28.82 | $18.76 | **$10.06** |
| LIGHT（`ds-flash`） | $16.37 | $15.35 | **$1.02** |
| **合计** | | | **$11.08** |

> **这不是优化，是合规修正**：`DATA_AND_COST_ANALYSIS.md` §4.1.2 与 PRD 22.2.6 直接冲突——前者假设所有异动都全额参与 LLM，后者明确 INFO 不参与、WARN 可选。**应以 22.2.6 为准**，同时修正成本模型。

**WARN 如何不损失信息**：Master 本来就在读全局证据，多看 10 行结构化列表的边际成本 < 1 次独立调用的 5%，但保留了 WARN 的全部信息量。列表项建议 `{rule_id, ts, severity, magnitude, asset}`，每项约 60 token。

### 4.2 O2：Master 输入瘦身

PRD 24.4 已要求：

> Master 只收结构化摘要 + 引用 ID，需要细节时用 Reflection 定向追问。

但 §4.1.2 中 Master 每次仍按 15,000 in 计入，**说明该要求从未落到成本模型**。

| 项 | 现状（1h） | 优化后（1h） |
|---|---:|---:|
| Master 输入 | 15,000 | **6,500** |
| ├ 子 Agent 摘要（6 个） | （含在上述 15,000 内） | 6 × ~400 = 2,400 |
| ├ 快照（裁剪视图） | — | 3,500 |
| └ WARN 列表（O1） | — | 600 |
| Master 输出 | 2,500 | **1,300**（O3） |

> **另一处 PRD 内部不自洽**：24.4 要求子 Agent 用「各自独立快照视图」，但 §4.1.2 的 1h 输入 33,000 显然是**合并视图**的量。实现时必须统一到「独立视图」，否则 token 降不下来。

### 4.3 O3：输出契约改「结论优先」（收益大，需监控）

**做法不是截断，而是改契约**：

| Agent | 输出契约 |
|---|---|
| Master | 结论 + 方向 + 概率 + **3 条依据（引用 `finding_id`）** + 2 条反证 + 失效条件；**禁止复述快照原文**，数值用引用代替 |
| 异动分析 | 触发解释 + 2 个情景 + 失效条件；**禁止复述指标定义** |
| 子 Agent | 摘要 + findings + 证据引用（不含原文复述） |

**必须配套的三个护栏指标**（否则准确率下降会被平均值掩盖）：

| 指标 | 含义 | 阈值 |
|---|---|---|
| `output_truncation_rate` | 输出触及 `LLM_MAX_OUTPUT_TOKENS` 的比例 | > 5% → **放宽契约，不要硬砍** |
| `schema_pass_rate` | 15 字段结构化输出合规率 | < 95% → 契约过紧或模型能力不足 |
| `verifier_mismatch_rate` | Python 复核不符率（O7） | > 2% → 换模型或改契约 |

> **硬截断是最危险的优化**：被截掉的通常是推理链尾部，而 `invalidation_conditions`（失效条件）恰好常在最后——它直接支撑第 5 章的 Invalidation Accuracy 指标。

### 4.4 O4：Prompt 缓存前缀固定化（唯一完全无损的降本手段）

缓存命中的是**完全相同的 token**，不改变任何输出。

**收益按缓存倍率排序**：

| 模型 | 基价（in） | 缓存价 | 倍率 | 备注 |
|---|---:|---:|---:|---|
| `deepseek-v4-flash` | $0.141 | $0.003 | **2.0%** | 缓存红利最大 |
| `deepseek-v4-pro` | $0.423 | $0.022 | **3.3%** | |
| `gpt-6.1-terra` / `claude-opus-5-5` | $1.00 / $4.00 | $0.05 / $0.20 | 5.0% | |
| `gpt-6-luna` / `claude-haiku-5-5` | $0.10 | $0.01 | 10% | 小模型缓存折扣最差 |

**实现前提**：

1. 前缀顺序固定：**system prompt → 工具定义 → 输出 schema → 示例 → [快照置后]**。
2. **TTL 与调用节奏匹配**：`analysis_1h` 每小时 1 次/资产，5 分钟 TTL **必然 miss**，必须用 **1 小时缓存写入**（Anthropic 1h 写入价 $4/M vs 5m $2.5/M），或让 1h / 15m / 4h 任务共用同一前缀以提高复用密度。
3. **缓存命中率必须单独入库**（`cache_read_tokens` / `cache_creation_tokens`），否则优化不可见。
4. 国内厂商的上下文缓存机制不统一（DeepSeek 自动前缀缓存 / Qwen 上下文缓存 / 智谱缓存存储限时免费），需在 Gateway 按 provider 分别实现。

### 4.5 O5 – O10 详解

**O5 `analysis_15m` 降频**：该任务产出**不推送、只聚合**（23.2.2），却贡献 LIGHT 输入的 52%（单资产 672,000/天）。降频到 8 次/天后，15m 中途的结构变化由 Python 异动规则覆盖（22.2.1 的 1m/5m/15m 规则本身是分钟级），LLM 不承担探测职责。

**O6 按 Agent 裁剪快照视图**：4.8 建议了 12 类快照字段，直接实现会让单次输入顶到 24K。裁剪要**在 Agent 职责范围内裁，不是在全局删字段**：

| Agent | 可见字段 |
|---|---|
| Technical | 多周期 OHLCV 摘要 + 技术指标 |
| Structure | Swing 点 + 支撑阻力区 + 突破回踩状态 |
| Derivatives | OI + Funding + Basis + 多空比 |
| Liquidity | 盘口 top20 摘要 + 成交额 + 集中度 |
| Regime | 多周期一致性 + 波动环境标签 |
| Risk | 数据质量标记 + 缺失项 + 账户/仓位（仅执行任务） |

**这同时提升准确率**：PRD 4.7 的核心设计是「专业 Agent 独立分析，减少过早互相影响」，全量投喂等于让每个 Agent 都去读不属于自己的证据。

**O7 可验证子 Agent 的 Python 复核器**（把「降级模型」从赌博变成工程）：

| 子 Agent 输出 | Python 可否独立复核 | 结论 |
|---|---|---|
| Technical（指标值、趋势） | 可（重算 EMA/RSI/MACD 比对） | **便宜模型零风险** |
| Derivatives（OI/Funding/基差解读） | 可（数值从库取回） | **便宜模型零风险** |
| Market Regime（状态标签） | 可（标签由规则引擎定义） | **便宜模型零风险** |
| Market Structure（关键位） | 可（Swing 点重算） | **便宜模型零风险** |
| Liquidity（盘口形态描述） | 部分（数值可查，形态描述不可） | 需人审抽检 |
| **Master（Bias / 概率 / 置信度）** | **不可** | **必须好模型** |

有复核器兜底后，LIGHT 档换最便宜的模型**不是准确率赌注，而是有校验的工程决策**；同时可由校验器在输出端强制归一化置信度档位，弥补小模型概率校准差的短板。

**O8 快照哈希记忆化**：`market_snapshots` 已有 `feature_version` / `schema_version` / `source_watermarks`（4.8），可直接对「该 Agent 关注的字段子集」算哈希。行情平静时结论必然不变，复用上次输出。**需给 `agent_outputs` 增加 `input_hash` 字段**（PRD 11.x 表清单要补）。

**O9 Batch / 错峰**：日报、周报、历史回填、模型对比实验全部可异步化 → Anthropic/OpenAI 五折、Kimi 六折、DeepSeek 错峰半价。**注意 Master 与异动分析不能走 Batch**（有时效要求），需按 Agent 类型在 Gateway 分流。

**O10 LIGHT 档 effort 降到 low**：LIGHT 承担抽取 / 分类 / 摘要，不需要长思考链。但**必须在 A/B 中确认**——不同厂商 effort 参数语义不同（Claude 用 `effort`，GPT 用 `reasoning_effort`），部分模型调低 effort 后输出 JSON 反而更不稳。

**O11 上下文长度护栏**：`claude-haiku-5-5` 在 prompt > 100K 时输入价从 $0.10 跳到 $0.50（**×5**）。Gateway 必须强制 `LLM_MAX_INPUT_TOKENS=24000`（24.2 已有）。

**O12 Schema 修复只回灌 output + error**：PRD v2.3 已规定「不重传原始上下文」。实现时若图省事重传全部上下文，**每次 schema 失败会把成本放大一倍以上**，且违反 O11。

### 4.7 明确不做（有准确率代价）

## 6. 选型结论

### 6.1 为什么「全 LIGHT」不是好方案

方案 A′ / D′ 表面最省，但**它把 Master 也降级了**——而 Master 是唯一直接产出 Bias、概率与置信度的环节，直接决定第 5 章 Direction Accuracy / Brier / Calibration 三个核心指标。

**正确的省法是**：把 6 个子 Agent（占 token 55%，按 PRD 24.1 本就偏确定性、且有 O7 复核器兜底）压到最便宜，把 Master 和 DEEP 保住。

### 6.2 各档推荐（约束：双通道可用 + ≤$50/月）

| 档位 | 推荐 | 备选（回退） | 理由 |
|---|---|---|---|
| **LIGHT** | `deepseek-v4-flash` | `gpt-6-luna` / `claude-haiku-5-5` | 抽取 / 分类类任务；缓存倍率 2%，前缀工程收益最大 |
| **STANDARD** | `gpt-6.1-terra`（预算允许时） | `deepseek-v4-pro` 闲时 | 唯一值得为准确率付溢价的档；terra 的 schema 遵循度通常优于国产 |
| **DEEP** | `claude-opus-5-5` | `qwen3.8-max` / `gpt-6.1-sol` | 量小（$11.65），准确率杠杆最高，**不要降级这一档** |
| **Reflection** | 复用 STANDARD，触发时升 `opus-5-5` | — | 触发少，一旦触发就是关键分歧 |

### 6.3 双通道分工

| 场景 | 主用 | 回退 | 说明 |
|---|---|---|---|
| LIGHT 抽取 / 摘要 | `deepseek-v4-flash` | `gpt-6-luna` | 国内直连（支付宝 / 微信、无需海外卡），主链路不受海外风控影响 |

## 7. 验证方法（如何证明「没有影响准确率」）

### 7.1 流程

1. **影子对照**：每项优化先影子运行（只记录不生效，PRD 24.5 已要求），对比**同一批快照**的输出。
2. **按 Agent 分组比指标**，禁止全局平均——否则高杠杆环节的改善会被低杠杆环节稀释。
3. **指标集**（5.2 / 33.3–33.5）：Direction Accuracy、Balanced Accuracy、Brier Score、Calibration、Interval Coverage、Target Hit Rate、Invalidation Accuracy。
4. **`evaluator_version` 锁定**（33.8）：优化前后窗口不得跨口径混合统计。

### 7.2 必须同时看的护栏指标

| 护栏指标 | 检出什么 | 阈值 |
|---|---|---|
| `schema_pass_rate` | O3 契约过紧 / 模型能力不足 | < 95% 告警 |
| `output_truncation_rate` | O3 截断了推理链 | > 5% → 放宽契约 |
| `verifier_mismatch_rate` | O7 复核不符（数值错） | > 2% → 换模型 |
| `cache_hit_rate` | O4 前缀工程是否到位 | < 40% → 调整 TTL / 前缀布局 |
| `degraded_ratio` | 降级 / 回退样本占比 | > 15% → 成本或可用性异常 |
| `by_agent_direction_accuracy` | 单个 Agent 的准确率退化 | 相对基线下降 > 3pp → 回滚该项优化 |

### 7.3 样本量与结论强度

| 优化项 | 影响面 | 30 天内可否得出结论 |
|---|---|---|
| O1（异动分级） | ~53% 的 STANDARD 输出 | ✅ 可（30 天约 7,500 次预测） |
| O2 / O6（输入瘦身） | 全部 Agent | ✅ 可（按 Agent 分组） |
| O3（输出契约） | 全部 Agent | ⚠️ 需按 Agent 分组单独看 |
| O5（15m 降频） | LIGHT 结构 / 技术 Agent | ⚠️ 仅看这 2 个 Agent 的分组指标 |
| O8（记忆化） | 平静行情样本 | ❌ 样本偏少，需跨月 |

> **样本量不足时必须输出 `INSUFFICIENT_SAMPLE`，不得给出误导性排名**（5.4）。

### 7.4 校准基线必须在优化前建立

`predictive_evaluations` 是不可再生的数据资产（依赖当时的模型 / Prompt / 快照版本）。**优化前必须先跑出一份完整基线快照**，否则优化后无法回答「准确率到底有没有变」。
