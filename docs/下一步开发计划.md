### 第 1 步：P4 收尾 —— 成本报表 + 多 Agent（3–5 天）

#### 1a. 成本分析报表（0.5 天）
数据源**已就绪**（`model_runs` / `llm_cost_records` 已有真实数据），
TODO 里标的就是「聚合 token 与费用」。

- 按 `model_id` / `tier` / `agent_name` / `prompt_version` / 日期聚合；
- **必须区分 `priced=false` 的行**（单价缺失记 0，
  直接求和会把「未定价」算成「免费」——与 L-05「键缺失 ≠ 费率为 0」同源）；
- 输出一张**可读的文本报表**（先不做前端），
  重点回答「这个月花了多少」「哪个 Agent 最贵」「哪版 Prompt 最烧 token」。

#### 1b. 多 Agent 拆分（2–4 天）
**PRD 4.7 的核心交付物**，目前完全没做。

子 Agent：Technical / Market Structure / Market Regime / Derivatives / Liquidity / Event-Risk

编排方式：**LangGraph**（2026-11-25 决策）。
已验证环境可用：`langgraph 1.2.22`，`StateGraph` / `Send` / reducer 三件套可用。
最小原型已跑通 fan-out → 子 Agent（互不可见）→ fan-in（冲突标注）。

关键纪律（**直接来自本项目已吃过的亏**）：
- **子 Agent 互不可见**（PRD 4.7）：并行 fan-out，不共享中间结论；
- **每次 Agent 调用写 `agent_runs` + `agent_outputs`**
  ——表已就位但**至今没有写入方**（又一个「有表无写入方」）；
  `agent_outputs` 写入必须与「模型调用计量」同纪律：
  **失败也写 `agent_runs`，绝不写伪造的 `agent_outputs`**；
- **Master 必须区分事实/推断/待验证假设**（PRD 4.7）——
  不能只是拼接子报告或多数投票；
- **同源指标不得重复计为独立支持**（PRD 4.7）；
- **Reflection 最多 1 轮，且针对具体争议点**。

**LangGraph 实现要点（原型已验证）**：
- **fan-out**：`add_conditional_edges(START, fan_out, [...])` +
  `Send(f"agent_{name}", {...})` 动态分叉
  （`Send` 从 `langgraph.types` 导入，**不在** `langgraph.graph` 里）；
- **并发写同一 state key 必须配 reducer**——
  不配则并发写入直接抛异常（`Annotated[list[dict], operator.add]`）；
- **fan-in**：普通节点汇总各分支输出并标注冲突；
- **子 Agent 互不可见**靠 `Send` 传的**局部 state** 实现——
  每个分支只带 `snapshot_id`，不带其他分支的输出。

> **先做 1a 再做 1b**：多 Agent 会让调用量成倍上升，
> **没有成本报表就无法判断拆分是否值得**。
> 而且成本报表本身就要验证「多 Agent 的计量是否正确」。

### 第 2 步：P5 调度层（3–4 天）

**「每天有结论」的前提**——目前全靠手动跑脚本。

- 建 `scheduled_jobs` / `job_runs` / `job_locks` 三表 + 迁移；
- 接入 `apscheduler`（**这正是它该被消费的地方**）；

- 异动扫描定时化（当前靠 `run_anomaly_scan.py` 手动）；
- **幂等与任务锁**（PRD 23.1.4）：同一 `job_id` 不并发；
- **补跑机制**：错过记 `MISSED`，补跑标 `BACKFILL`，不占实时配额；
- **关机恢复**：优先补数据，再生成当前分析（PRD 20.2 第 12 条）。

- 飞书连通性验证（PRD 28.2 第 1 项）；

### 第 4 步：P7 口径 → 追踪 → 评估（5–7 天）

**顺序不能反**——PRD 第 33 章的口径必须**先定稿**，
