#### 1b. 多 Agent 拆分（2–4 天）

编排方式：**LangGraph**（2026-11-25 决策）。

关键纪律（**直接来自本项目已吃过的亏**）：
- **子 Agent 互不可见**（PRD 4.7）：并行 fan-out，不共享中间结论；
- **每次 Agent 调用写 `agent_runs` + `agent_outputs`**
  ——表已就位但**至今没有写入方**（又一个「有表无写入方」）；
  `agent_outputs` 写入必须与「模型调用计量」同纪律：
  **失败也写 `agent_runs`，绝不写伪造的 `agent_outputs`**；
- **Master 必须区分事实/推断/待验证假设**（PRD 4.7）——
  不能只是拼接子报告或多数投票；
- **同源指标不得重复计为独立支持**（PRD 4.7）；
- **Reflection 最多 1 轮，且针对具体争议点**。

**LangGraph 实现要点（原型已验证）**：
- **fan-out**：`add_conditional_edges(START, fan_out, [...])` +
  `Send(f"agent_{name}", {...})` 动态分叉
  （`Send` 从 `langgraph.types` 导入，**不在** `langgraph.graph` 里）；
- **并发写同一 state key 必须配 reducer**——
  不配则并发写入直接抛异常（`Annotated[list[dict], operator.add]`）；
- **fan-in**：普通节点汇总各分支输出并标注冲突；
- **子 Agent 互不可见**靠 `Send` 传的**局部 state** 实现——
  每个分支只带 `snapshot_id`，不带其他分支的输出。

**7 条纪律全部落地并有反向验证**（`scripts/verify_test_effectiveness.py`
共 **47 个用例**，47/47 全通过）：

1. **子 Agent 互不可见**——由 `Send` 的**局部 state** 结构保证，
   不是靠约定；测试断言「精确的键集合」，
   弱断言（只查某几个词）恒真、锁不住缺陷；
2. **同源指标不得重复计为独立支持**——按**数据来源域**分组，
   `ohlcv` 域内 3 个 Agent = **1 个**独立来源；
3. **失败绝不伪造输出**——失败的 Agent 只写 `agent_runs`，
   `agent_outputs` **零伪造**；
4. **Master 区分事实/推断/假设**——`【事实】``【推断】``【假设】`
   标注在转换时**原样保留**；
5. **方向性分歧先识别再保留**——`UP` vs `DOWN` 算冲突，
   `UP` vs `FLAT`（证据不足）**不算**（否则假分歧淹没真分歧）；
6. **子 Agent 崩溃不拖垮整次分析**——异常在节点内被隔离，
   其余 5 个的结果保住；
7. **计量走同一条路径**——`model_runs.agent_name` 记录**实际发起调用的 Agent**，
   成本报表「哪个 Agent 最贵」才答得出来。

**过程中发现并修掉的两个真实缺陷**：

- **LangGraph fan-out 是真并行**（6 个线程），
  而 SQLAlchemy `Session` **不是线程安全的**——
  并发 `add()` + `flush()` 触发
  `duplicate key value violates unique constraint "pk_llm_cost_records"`。
  修法：**分支线程只做网络调用，DB 写入全部在主线程串行完成**。
- `model_runs.agent_run_id`（指向 `agent_runs.run_id` 的外键列）
  **此前恒为 NULL**——列建了、索引建了，却从没有写入方。
  修法：`agent_runs` 改为**两阶段写入**（`RUNNING` → 终态），
  先 flush 拿到 `run_id` 再回填。
